git worktree Cheatsheet · Fundamentals

Multiple working directories from a single repository — no more stash-and-switch.

Key concept One .git, many checkouts.
Each worktree is its own folder on its own branch, sharing the same history & remotes.
git … = shell command path = directory you choose flag = important option · = alternatives

1 Create a Worktree

Check out existing branch in new dir
git worktree add ../feat feat
Create new branch and worktreemost common — start fresh work
git worktree add -b feat ../feat
Branch from a specific base
git worktree add -b hotfix ../hot main
Track a remote branche.g. review someone's PR
git worktree add --track -b feat ../feat origin/feat
Detached at a commit / tagread-only inspection
git worktree add --detach ../old v1.2.0
Force when path is dirty or branch is busy
-f

2 List & Inspect

Show all worktrees
git worktree list
Verbose: locks & prunable info
git worktree list --verbose
Machine-readable output
git worktree list --porcelain
Which branches are taken+ marks branches checked out elsewhere
git branch
Where am I?prints this worktree's root
git rev-parse --show-toplevel

3 Remove & Prune

Remove a clean worktreedeletes the directory
git worktree remove ../feat
Force-remove (uncommitted changes!)
git worktree remove -f ../feat
Clean stale admin entriesafter deleting a worktree dir manually
git worktree prune
Preview what would be pruned
git worktree prune --dry-run -v
Delete branch tooafter removing the worktree
git branch -D feat

4 Move, Lock & Repair

Move a worktreeupdates internal paths
git worktree move ../old ../new
Fix broken links after manual move
git worktree repair
Lock so it can't be prunede.g. worktree on a USB drive
git worktree lock --reason "usb" ../bak
Unlock
git worktree unlock ../bak

5 Common Workflows

Hotfix without disturbing current work
git worktree add -b hotfix ../hot main
Review a PR locally
gh pr checkout 123 --branch pr-123
Diff between two branches side-by-sideopen both worktrees in your editor
cd ../feat && code .
Run long test on one branch while coding another
cd ../ci && npm test
Throwaway sandbox at HEAD
git worktree add --detach ../scratch

6 Concepts & Gotchas

Main repo has a .git directory; linked worktrees have a .git file pointing back
A branch can only be checked out in one worktree at a timeswitch with git switch or use a different branch
Worktrees share stash, refs, remotes, hooks & configthey're not independent repos
Submodules & node_modules aren't shared — install in each
Place worktrees outside the main repo to avoid Git confusion

7 Node.js / Next.js Tips

Clone-copy node_modulesAPFS copy-on-write: instant, ~0 disk
cp -cR ../base/node_modules .
Reconcile after package-lock.json change
npm ci
Never share .next/ between worktreesbuild cache + SWC artifacts are branch-specific
rm -rf .next
Avoid symlinking for next devfsevents watchers + dup React = pain
Force a clean install if odd errors appear
rm -rf node_modules .next && npm ci
npm cache is global & shared — fast re-installsno setup needed
npm config get cache
Quick start recipe  ·  You're on main mid-task and a hotfix lands. Instead of stashing: git worktree add -b hotfix ../myrepo-hotfix main → cd ../myrepo-hotfix → fix, commit, push, open PR → cd - back to your original work, untouched. When the PR merges: git worktree remove ../myrepo-hotfix and git branch -D hotfix.

Rescue commands  ·  Stale entry after rm -rf? git worktree prune. Moved a folder in Finder? git worktree repair. "Branch is already checked out" error? Use a different branch, or remove the other worktree first.
